# Garage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save the car you're sitting in, with all its customisation, to a garage file, and call it back later. It appears empty on a road 30–60 m away with a blip.

**Architecture:** A new module, `src/garage.cpp`, owns the saved-car list and `SPESP_garage.ini`. It reads the full setup from a vehicle and puts it back on a newly spawned one, and it tracks the one called car and its blip. `menu.cpp` gets a third page, Garage, which opens from the menu or from its own hotkey (Numpad `+`). Calling a car waits for the model to stream in, which needs `scriptWait`, so it runs deferred from `MenuTick`, the same way teleport does.

**Tech Stack:** C++17, MSVC, CMake, ScriptHookV SDK 1.0.617.1a. Natives are called by hash through `Invoke<R>` in `src/invoke.h`.

**Spec:** `docs/superpowers/specs/2026-11-19-garage-design.md`

## Global Constraints

- Copy every new native hash from `sdk/inc/natives.h`; never write one from memory. The table in Task 1 was copied from there. Update the "checked against natives.h" comment.
- The only world writes allowed are spawning, configuring, blipping, releasing and deleting **our own called car**. Never touch other vehicles or peds.
- Nothing goes through the game's cheat system.
- Hotkey default `VK_ADD` (Numpad `+`). Home, F1–F3 and F5–F8 are off limits.
- Damage and dirt aren't saved. A called car arrives clean (dirt 0), unlocked, with the engine off.
- Only one car is out at a time.
- Interior, dashboard and xenon colours aren't in the 2016 SDK, so they're not saved. The README must say so.
- Build: `"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe" --build build --config Release`. It must finish with no errors and no new warnings.
- There are no tests. Each task is verified by a clean build. In-game checks are listed for the user and must never be claimed as done.
- Commits: a short imperative subject, then `- ` bullets. Never add `Co-Authored-By` or any AI attribution. Use `git -c safe.directory='*'`, because the repo trips git's ownership check.
- `README.md` must stay in sync: the feature text, the hotkey table, `[Keys] Garage`, the `[Garage]` ini keys, the garage file and the code layout.

## Review Focus

1. **Saving a car you can't save.** Saving on foot, or in a boat, helicopter, plane or train, shows a notification and saves nothing. Only cars, bikes, quads and bicycles can be saved, since calling one means placing it on a road. (Task 1)
2. **No road nearby.** In the desert, on a rooftop or in an interior with no road node in range, the car still appears: next to the player, never underground or in the sea. (Task 2)
3. **The model won't load.** A hand-edited bad model, or a DLC car that's missing, gives up after 5 s with a notification. No hang, no crash, and the previous car is kept. (Task 2)
4. **The called car is gone.** If it's destroyed, despawned, or you switch character, the blip is removed and the handle cleared, and calling again works. A destroyed car gives a notification. (Task 2)
5. **A bad garage file.** Missing keys use the stock value. A plate longer than 8 characters is cut to 8. An unknown or zero model hash makes the entry show `(invalid)`, and calling it fails cleanly. (Task 1)

- [ ] **Step 1: Add the natives, `IniPath()`, the `[Garage]` blip settings and the `FindVehicleMake` export.** Settings follow the four-place rule, except for the menu, since these are ini-only.

- [ ] **Step 2: In `garage.cpp`, write `SavedCar Capture(Vehicle v)` and `void Apply(Vehicle v, const SavedCar& c)`.**
  Capture: mods 0–49 via `GET_VEHICLE_MOD` (slots 17–22 are toggles: turbo = 18, tyre smoke = 20, xenon = 22, read with `IS_TOGGLE_MOD_ON`); variations for slots 23 and 24; extras 0–14 only where `DOES_EXTRA_EXIST`. Apply order matters:
  1. `SET_VEHICLE_MOD_KIT(v, 0)` and wheel type
  2. mod colours 1 and 2
  3. `SET_VEHICLE_COLOURS`, extra colours, then the custom RGB colours if flagged
  4. colour combination, but only if `primary`/`secondary` weren't captured; otherwise skip it, since it overwrites colours
  5. mods, where slots 23 and 24 pass their variation as `customTires`
  6. toggles, extras, livery, tint, neon and neon colour, smoke colour, plate text and style, bulletproof tyres

  Never call `Apply` on a vehicle other than the one we just created.

- [ ] **Step 3: Write the file IO.** Path: `IniPath()` with `.ini` replaced by `_garage.ini`. Use one section per car, `[Car1]`…`[CarN]`, and rewrite the whole file on every save or delete: delete the file, then write the sections. Keys: `Name`, `Model` (hex), `Mods` (50 comma-separated ints), `ModVariation`, `Turbo`, `TyreSmoke`, `Xenon`, `WheelType`, `Colours` (primary,secondary,pearl,wheel), `Paint1` (type,colour,pearl), `Paint2` (type,colour), `CustomPrimary` / `CustomSecondary` (`r,g,b` or empty), `ColourCombination`, `Extras` (15 ints), `Livery`, `WindowTint`, `Neon` (4 bools), `NeonColour`, `SmokeColour`, `Plate`, `PlateStyle`, `BulletproofTyres`. Missing keys keep the `SavedCar` defaults (stock: mods -1, extras -1, other ints 0, livery -1, plate empty = leave as spawned). Cut `Plate` to 8 characters. Cap the list at 40 cars.

- [ ] **Step 4: Write `GarageSaveCurrent()`.**
  - Not in a vehicle → `Notify("Get in a car to save it")`, return false.
  - The model isn't a car, bike, quad or bicycle → `Notify("Only road vehicles can be saved")`, return false.
  - The garage is full (40) → `Notify("Garage is full (40 cars)")`, return false.
  - The vehicle is the currently called car (Task 2 exposes `GarageCalledIndex()`; in this task treat it as -1) → overwrite that entry and notify `Updated <name>`.
  - Otherwise append and notify `Saved <name>`.
  - Write the file in either case.

- [ ] **Step 5: Hook `GarageLoad()` into `LoadSettings`/`ReloadSettings`, and add `src/garage.cpp` to `CMakeLists.txt`.**

- [ ] **Step 1: Write `bool FindSpawnSpot(const Vec3& me, Vec3& pos, float& heading)` to choose the spawn spot.**
  1. Scan nodes n = 1..60. Take the first one 30–60 m away (2D distance) where `!IS_SPHERE_VISIBLE(x, y, z, 3.0f)`.
  2. Else take the first node 30–60 m away, visible or not.
  3. Else take the first node 10–120 m away.
  4. Else use 6 m in front of the player (`GET_OFFSET_FROM_ENTITY_IN_WORLD_COORDS` 0,6,0) with the player's heading, and return false so the caller knows it's the fallback.

- [ ] **Step 2: Write `GarageCall(index)`.**
  1. If the entry's model fails `IS_MODEL_IN_CDIMAGE && IS_MODEL_A_VEHICLE`, notify `Can't load <name>` and return, keeping the previous car.
  2. `REQUEST_MODEL`, then wait up to 5000 ms (`GET_GAME_TIMER`, `scriptWait(0)`). On timeout, notify the same message and return.
  3. Retire the previous car. Remove its blip. If it exists, the player isn't in it and `!IS_ENTITY_ON_SCREEN`, delete it (`SET_ENTITY_AS_MISSION_ENTITY(v,1,1)` then `DELETE_VEHICLE(&v)`). Otherwise `SET_VEHICLE_AS_NO_LONGER_NEEDED(&v)`.
  4. Spawn with `CREATE_VEHICLE`, then `SET_VEHICLE_ON_GROUND_PROPERLY`, `Apply`, dirt 0, doors 1, `SET_VEHICLE_ENGINE_ON(v,0,1,1)`, owned by player 1, needs hotwire 0, stolen 0, `SET_MODEL_AS_NO_LONGER_NEEDED`.
  5. Add the blip: sprite, colour, and the name via the blip-name text commands with `ADD_TEXT_COMPONENT_SUBSTRING_PLAYER_NAME(name)`.
  6. Notify `<name> is waiting nearby`, or `<name> is next to you` on the fallback.

- [ ] **Step 3: Write `GarageTick(player)`.** If no car is out, return.
  - The car no longer exists → remove the blip and clear the state, with no notification.
  - `IS_ENTITY_DEAD` or `!IS_VEHICLE_DRIVEABLE(v,0)` → `Notify("<name> was destroyed")`, remove the blip, `SET_VEHICLE_AS_NO_LONGER_NEEDED`, and clear.
  - Otherwise set the blip display to 0 while `IS_PED_IN_VEHICLE(player, v, 0)` and 2 otherwise, calling it only when this changes.
  - `PLAYER_PED_ID` changes when you switch character, so a car stays tied to the garage, not to the character. That's fine.

- [ ] **Step 4: Make `GarageSaveCurrent` use `GarageCalledIndex()` for the update-in-place case.** Make `GarageDelete` keep `GarageCalledIndex()` correct: if the deleted entry is the called one, the index becomes -1 but the car stays out; if it's earlier in the list, the index shifts down by one.
